# 공지관리 목록 성능 검증

- API·권한·공지 공통 게시글·기존 읽음/수정/삭제 회귀: npm test 39개 통과.
- UI 계약: npm run test:ui 6개 통과.
- 기존 브라우저 하네스: PC 1440×1000, 모바일 390×844 통과.
- 신규 하네스 npm run test:notices: 예시 공지 400건, 첫 화면 30건, 스크롤 다음 페이지, 아직 표시되지 않은 글 검색, 검색 초기화, 메뉴 복귀 시 로드된 목록 유지, 비활성 관리 API 조회 생략 검증.
- 열람 인원 집계는 사용자별로 모든 읽음 기록을 반복 탐색하지 않고 집합으로 계산하며 공통 공지/이전 개별 공지의 기존 의미를 유지.
- 목록 전송과 DOM 생성은 30건으로 제한. JSON/Redis 원본 컬렉션 읽기는 기존 저장 구조를 유지하므로 저장소 전체 조회 자체의 비용은 남아 있음.
- 운영 사용자 자료를 사용하지 않았고 운영 환경의 응답 시간 개선율은 측정하지 않음.
