# 모바일 입력 확대 점검

## 관찰과 한계

제공된 iPhone 화면에서 왼쪽 내용과 상단 헤더가 일부 잘린 모습은 확인했습니다. 정지 이미지에는 visualViewport 배율이나 로그인 전 화면이 없으므로 입력 자동 확대·사용자 확대·WebView 상태 중 어느 원인인지 단정하지 않습니다.

현재 로그인/가입/비밀번호 입력에는 이미 16px 이상 규칙이 있습니다. 로그인 자체의 작은 입력 글꼴이 원인이라고 확인한 것은 아닙니다. 전체 코드 점검에서는 다음 미보호 영역을 찾았습니다.

- 메모 검색/색상/서식 선택상자: 브라우저 기본 크기 또는 작은 상위 글꼴 상속
- 작성 도구의 select: 14px 규칙
- 메모 보조 입력, 게시판 참조 선택/검색: 화면 글꼴 14px 설정 또는 브라우저 기본 크기 상속
- 관리자 화면 설정/권한/로그 분류 select: font:inherit로 14px 설정 상속
- 기존 보호 영역: 로그인·가입·비밀번호, TODO 인라인, 날짜, 텍스트 불러오기, 프로필, 코드 편집, 참조 입력

## 개선

모든 HTML 진입 화면에 mobile-inputs.css를 마지막으로 적용합니다. 좁은 화면 및 터치 중심 기기의 텍스트 input/textarea/select/contenteditable 루트는 최소 16px이며 18/20px 사용자 설정을 유지합니다. 체크박스·라디오·범위·색상·파일·버튼에는 글꼴 강제를 하지 않습니다. 메모 제목, 게시글/공지 제목, 게시판 이름과 리치 본문의 기존 큰 글꼴은 별도 변수로 보존합니다.

html의 text-size-adjust:100%는 화면 전환 시 브라우저 자동 글자 확대를 안정화합니다. viewport의 사용자 확대를 제한하거나 최대 배율을 고정하지 않습니다. 로그인 성공 시 로그인 폼의 활성 입력만 blur하고, 실패 시 초점을 바꾸지 않습니다. 기존 사용자 배율 강제 초기화·transform 축소·새 로그인 권한을 사용하지 않습니다.

## 검증

- 전체 Node 테스트와 UI 계약 테스트 실행
- 새 계약 테스트: 모든 HTML 마지막 CSS 로딩, 확대 허용 viewport, 입력 종류와 미디어 범위, 큰 제목, 성공 후 로그인 blur
- 독립 코드 검토: 작은 글꼴 위험 영역과 큰 제목/본문 보존 재확인
- 실제 Safari/iPhone에서 로그인 및 키보드 후 배율이 유지되는지는 이 실행 환경에서 검증할 수 없습니다. Chromium도 socket 제한으로 실행되지 않았습니다.
- `/mobile-input-harness.html`: 실제 계정/API/저장 없는 입력 테스트. 본문 14/20px, 예시 로그인 전환, 검색/날짜/분류/숫자/본문/작은 도구/큰 제목/편집 영역의 실제 글꼴 및 visualViewport 배율을 표시합니다. 권한 우회나 실제 로그인 폼이 아닙니다.

실기기에서 각 필드를 순서대로 눌러 화면이 좌우로 잘리지 않는지, 키보드 열기/닫기·가로 회전·로그인 전환·실패 시 입력 유지·손가락 확대를 확인해야 합니다.
