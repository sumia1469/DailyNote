# 캘린더 검증 기록

2026-10-01 한국 시간. 운영 Redis·실제 사용자 자료를 사용하지 않고 임시 JSON 저장소·예시 계정으로 확인했습니다.

- Node 자동 테스트 32개, UI 계약 5개 통과.
- PC 1440×1000, 모바일 390×844: 월간·주간·일간, 기간 막대, 시간 겹침, 종일·휴무, 날짜 이동, 날짜별 투두·메모·파일, 상세 진입과 캘린더 복귀.
- 일정 등록·수정·삭제·재조회·새로고침, 시간 역전 거부, 저장 실패 후 입력 유지 및 재시도.
- 앱 내 알림 노출, 한국 시간 시각, 사용자별 localStorage 중복 억제, 새로고침 후 중복 없음.
- 권한 거부, 타인 자료 숨김, 계정 전환 후 이전 일정·알림 초기화, 화면 이동 후 늦은 응답 무시.
- 공통 디자인 하네스, 외부 요청 없음, 모바일 입력 16px, 화면 가로 넘침 없음.
- 기존 공통 화면 회귀 및 참조 이미지 미리보기·확대·원래 화면 복귀 하네스 확인. 320×568·844×390 계정 메뉴 하단도 확인.

실제 iPhone 알림 권한·절전·키보드는 기기에서 별도 확인이 필요합니다. 앱 종료 상태의 푸시는 구현 범위가 아닙니다.

## 간결한 화면 재검증 (2026-10-01)

- 자동 테스트 38개·UI 계약 6개 통과. 기존 Redis의 빈 하위 `{}`와 문자열 목록을 정규화합니다.
- 조회 팝업 날짜 이동·내용 검색·취소/전체 보기, … 메뉴의 기기 알림 노출·바깥 클릭/Escape 닫기를 확인합니다.
- PC·모바일의 짧은 월간 달력, 제목 양옆 화살표, 하단 오늘 버튼, ＋ 등록 및 기존 CRUD/권한/알림 회귀를 검증합니다.

### 등록 날짜 입력 폭 수정

종일 date·시간 datetime-local 입력과 조회 date에 appearance/inline-size 제한을 적용하고 부모 grid의 최소 폭을 0으로 설정합니다. 390px·320px에서 시작/종료와 제목 입력의 폭 일치, 가로 넘침 없음, 종일 전환과 값 유지, 16px 글꼴을 Chromium 브라우저 하네스로 확인합니다. 실제 iOS 네이티브 날짜 선택기는 기기에서 별도 확인이 필요합니다.

모바일 일정 수정 팝업의 삭제/삭제 확인 버튼은 별도 전체 폭 행에 배치하고 취소·저장은 다음 행에 표시합니다. 320×568에서 확인 문구와 버튼이 팝업 안에 보이고 재확인 삭제가 완료되는지 검증합니다.
