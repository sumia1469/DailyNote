# 캘린더

좌측 메뉴의 **캘린더**를 엽니다. 기존 헤더와 동일하게 오른쪽 ＋에서 일정을 등록합니다. 월간·주간·일간 버튼으로 표시 방식을 바꾸고 오늘·이전·다음·날짜 입력으로 이동합니다.

- 월간: 여러 날에 걸친 일정은 날짜 칸을 이어 붙인 막대로 표시합니다. 같은 주의 막대가 세 줄을 넘으면 날짜의 +건수에서 전체 일정을 확인합니다.
- 주간·일간: 시간표의 빈 시간을 눌러 등록할 수 있습니다. 겹치는 시간 일정은 나란히, 종일 일정은 상단에 표시합니다. 모바일 주간 시간표는 내부에서 가로 스크롤합니다.
- 날짜 선택: 스케줄·일일 투두·메모·파일을 날짜별로 모아 봅니다. 투두는 업무일자, 메모는 작성일, 파일은 등록일을 사용합니다. 각 자료의 링크로 기존 상세페이지를 열 수 있습니다.
- 일정: 제목, 종류(일정 또는 휴무·휴가), 색상, 시작·종료, 종일, 알림, 일정 메모를 등록합니다. 종일 종료일은 포함하고 시간 일정 종료 시각은 포함하지 않습니다. 모든 시간은 한국 시간입니다.
- 휴무·휴가: 종일로 등록하며 주말·공휴일과 함께 날짜에 표시됩니다. 일정은 본인에게만 보입니다.
- 수정·삭제: 막대 또는 날짜 목록의 일정을 누릅니다. 삭제는 팝업에서 삭제 → 삭제 확인 순서입니다. 저장 실패 시 입력을 유지합니다.

## 알림 범위

알림은 없음·시작 시·5/10/30분 전·1시간 전·1일 전입니다. 종일 일정은 시작일 오전 9시 기준입니다. 로그인 중인 앱에서 30초마다 확인하고, 현재 메뉴와 상관없이 사이트 안에 알림 카드를 표시합니다. 지원하는 기기는 **기기 알림 켜기**를 직접 눌러 브라우저 알림을 허용할 수 있습니다. 허용하지 않아도 사이트 안 알림을 받습니다.

앱이나 브라우저가 닫혀 있거나 기기가 절전 상태면 정시 알림을 보장하지 않습니다. 백그라운드 푸시·서비스워커·서버 발송은 제공하지 않습니다. 다시 열린 시점에 아직 진행 중이거나 예정된 일정의 최근 24시간 내 알림을 확인합니다. 동일 브라우저·사용자·일정 버전의 알림은 localStorage로 중복 표시를 줄입니다. 다른 기기나 동시 탭 사이의 정확히 한 번 발송은 보장하지 않습니다. 알림은 공지사항 게시판과 분리되어 기존 공지·열람 상태를 변경하지 않습니다.

## 공휴일 데이터와 출처

2026·2027년 대한민국 공휴일·대체공휴일을 로컬 파일에 포함합니다. 외부 API를 호출하지 않으며 공식 자료가 없는 다른 연도는 안내를 표시하고 주말·직접 등록한 휴무만 표시합니다. 임시공휴일 지정이나 법령 변경·새 연도는 파일을 갱신해야 합니다.

- 우주항공청 2026년 월력요항(한국천문연구원 재게시): https://www.kasi.re.kr/kor/publication/post/newsMaterial/32031
- 우주항공청 2027년 월력요항, 2026-06-29 발표: https://www.kasa.go.kr/prog/plcyBrf/brief/kor/sub01_01_04/view.do?plcyBrfNo=431
- 한국천문연구원 연도별 달력 자료: https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2027

2027년 공식 발표에 명시된 2026년부터 적용된 노동절·제헌절 공휴일 지정도 반영합니다. 출처의 날짜·명칭 정보만 사용하며 본문을 복제하지 않습니다.

## 개발과 권한

- `public/calendar-core.js`: 한국 시간 날짜, 기간, 겹침 배치, 알림 시각 계산. 서버와 클라이언트가 공유합니다.
- `public/calendar-holidays.js`: 확인한 연도별 공휴일 스냅샷.
- `public/calendar.js/css`: 공통 UIConfig·AppShell에 연결한 업무 모듈. 외부 UI 플러그인 없음.
- `src/calendar.routes.js`: `/api/calendar?start=YYYY-MM-DD&end=YYYY-MM-DD`로 기간과 접근 가능한 날짜별 자료를 조회합니다. end는 조회 제외 날짜이며 최대 370일입니다. POST는 등록, `/api/calendar/:id`의 GET/PUT/DELETE는 조회·수정·삭제입니다.
- `calendar_events` 컬렉션: 기존 JSON 또는 Redis에 저장합니다. 새 환경 변수는 필요하지 않습니다.
- `calendarRead/Create/Edit/Delete` 권한을 기본 사용자 권한과 관리자 설정에 연결합니다. 타인 일정은 관리자에게도 개인 API에서 공개하지 않습니다. 날짜별 자료는 기존 `worklogRead/memoRead/fileRead`도 확인하며 큰 첨부 원문·저장 경로는 목록 응답에서 제외합니다.
- 화면 전환과 계정 변경은 요청 번호·계정 세대로 늦은 응답을 무시합니다. 등록·수정·삭제 중 중복 제출과 닫기를 차단합니다.

검증: `npm test`, `npm run test:ui`, 선택적 Playwright 개발 환경의 `npm run test:calendar`. 테스트는 임시 JSON 데이터와 예시 계정만 사용합니다. 실제 iPhone 절전·알림 권한은 별도 기기 확인이 필요합니다.
