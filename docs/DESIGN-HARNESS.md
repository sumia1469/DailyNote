# UI 디자인 계약 및 하네스

## 목적

사용자와 관리자의 메뉴를 바꿔도 같은 위치·크기·방식으로 조작하도록 공통 셸을 유지합니다. 하네스는 공통 UI 규칙을 실제 브라우저에서 확인하는 예시 화면이며 문서·메뉴 선언·Node 계약 테스트와 함께 회귀 검증 기준입니다.

## 확정 디자인

| 항목 | 규칙 | 구현 |
| --- | --- | --- |
| 헤더 | 높이 76px, fixed, 중앙 현재 메뉴명 | `.ui-header`, `.ui-title` |
| 좌우 슬롯 | PC 각각 92px, 모바일 각각 88px | 대칭 grid, 제목은 화면 중앙 |
| 버튼 | 42×42 원형, 로컬 선 아이콘 | `.shell-icon`, `.ui-actions` |
| 왼쪽 | 모든 화면에서 숨김 메뉴 | `UIShell.drawer()` |
| 우측 | 등록 가능한 화면은 ＋; 일지는 검색도 표시 | `UIConfig.actions`, `UIShell.actions()` |
| 본문 | 전체 폭, 모바일 좌우 12px, PC 24px | 화면 셸 |
| 팝업 | 둥근 24px, 화면 안 스크롤, 배경 구분 | `dialog`, `.admin-dialog`, `.journal-dialog` |
| 공지 목록 | 본문 제목·설명 없음, 항목만 표시 | `#view-notifications` |
| 공지 상세 | URL로 이동, 중앙 공지 상세, 왼쪽 뒤로가기 | `#notifications/ID` |
| 톤 | 흰색·회색, 기존 사용자 색상 설정 유지 | 로컬 CSS 변수 |

헤더 제목이 길면 한 줄 말줄임으로 처리합니다. 제목 슬롯이 좌우 버튼 수에 따라 밀리면 안 됩니다. 메뉴 접근 가능 여부와 액션 표시를 권한으로 계산하되 서버 검증을 대체하지 않습니다.

## 컴포넌트·업무의 경계

`ui-config.js`: 선언, 메뉴 제목·패널·읽기 조건·등록 액션.
`ui-shell.js`: DOM에 제목·액션 적용, 숨김 메뉴의 inert·포커스·Escape·Tab, 팝업 바깥 클릭.
`ui-shell.css`: 공통 스타일의 최종 기준.
업무 어댑터: API·데이터·폼·라우트. 공지 상세 데이터는 사용자 어댑터, 관리자 저장은 admin.js가 담당합니다.

상세 본문·행 내용은 사용자 입력이므로 textContent로 렌더링합니다. 외부 스크립트·UI 의존성을 추가하지 않습니다. 비동기 응답은 현재 화면이 아니면 무시합니다.

## 새 메뉴 추가 순서

1. UIConfig의 해당 scope에 `{id,title,icon,panel,read,actions}`를 선언합니다.
2. 사용자/관리자 HTML에 본문 패널과 숨김 메뉴 링크를 추가합니다. 기존 공통 헤더를 재사용합니다.
3. 등록 업무라면 ＋ 액션의 permission·dialog를 연결합니다. 설정 메뉴는 빈 actions입니다.
4. 등록·수정 페이지의 제목·폼·오류·진행·뒤로가기·취소를 구성합니다.
5. 업무 JS에 데이터 조회·저장·권한 처리만 연결합니다. 헤더 위치는 개별 변경하지 않습니다.
6. 하네스와 UI 계약 테스트에 새 메뉴를 포함하고 온보딩·README를 갱신합니다.

## 팝업 계약

＋ 등록은 새 폼, 수정은 기존 값과 ID를 채웁니다. 성공 시 작성 페이지를 닫고 목록을 갱신합니다. 실패 시 작성 페이지와 입력을 유지합니다. 제출 버튼을 비활성화해 중복 요청을 막습니다. 제출 중 Escape·바깥 클릭은 차단하고 완료 후 닫을 수 있게 합니다. 작성 페이지는 배경 메뉴의 포커스를 차단하고 출발 버튼으로 복귀합니다. 업무 로직과 필수 입력 검증은 기존 어댑터가 유지합니다.

## 하네스 사용법

`npm start` 후 `/design-harness.html`을 엽니다. 역할과 메뉴를 바꾸면 같은 UIConfig에서 제목·액션을 읽습니다. ＋로 예시 작성 페이지를 열고 빈 입력 저장을 눌러 오류 유지, 입력 후 저장으로 성공 종료를 확인합니다. 숨김 메뉴·Escape·Tab·복귀 포커스를 확인합니다. 체크 실행은 현재 화면의 제목 중앙, 가로 넘침, 중복 ID, 등록 버튼 위치를 보고합니다. 해상도를 PC·모바일로 바꿔 반복합니다.

하네스는 API 테스트를 대체하지 않습니다. 목록 예시는 운영 자료와 연결되지 않습니다. 사용자 공지 상세의 읽음·소유권은 실제 API 테스트와 실제 사용자 셸에서 검증합니다.

## 승인 기준

- 사용자 5개, 관리자 5개 메뉴가 중앙 제목을 공유합니다.
- 메뉴 닫힌 상태에서 숨김 컨트롤이 포커스를 받지 않습니다.
- 사용자 공지 본문에 제목·설명이 반복되지 않고 상세 URL 직접 접근·뒤로가기가 됩니다.
- ＋ 표시가 권한·메뉴에 맞으며 등록·수정이 전체 작성 페이지로 열립니다.
- 팝업 오류는 입력을 유지하고 재제출 가능해야 합니다.
- PC·모바일 가로 스크롤과 헤더 겹침이 없습니다.
- `npm test` 통과, 실제 브라우저 검증 결과 기록, 문서 갱신 완료.

## 공지사항 기능 (2026-10-01)

이 메뉴는 사이트 내 공지 게시판입니다. 푸시 알림·브라우저 알림 권한·백그라운드 발송을 사용하지 않습니다. 사용자 메뉴는 **공지사항**, 관리자 메뉴는 **공지 관리**입니다. 숫자 배지는 미열람 공지 수입니다. 사용자 목록에서 제목을 누르면 상세페이지로 이동하고 열람 처리합니다. 기존 제목 없는 공지는 내용을 목록 제목으로 표시합니다.

관리자는 ＋ 작성 페이지에서 제목(선택, 최대 120자)과 내용(필수, 최대 2000자)을 작성합니다. 공지는 모든 승인된 사용자가 함께 보는 게시글 한 건이며 이후 가입자도 조회합니다. 관리자 목록도 게시글당 한 번만 표시하고 열람 인원/전체 인원을 보여 줍니다. 제목·내용 검색과 열람/미열람 사용자 있음 필터를 제공합니다. 공통 글 수정·삭제는 전체에 적용하며 수정하면 사용자별 읽음을 초기화합니다. 기존 업데이트 공지 복사본은 releaseId로 연결하고 이전 읽음·상세 URL을 유지합니다. 이전 개별 공지는 원래 게시 대상만 조회하며 동일 시각·제목·내용의 과거 일괄 게시 기록은 관리자 목록에서 묶어 관리합니다.

호환성을 위해 API `/api/notifications`, `/api/admin/notifications`, 상세 URL `#notifications/ID`, 저장소 `notifications`, 권한 키 `notifications`·`notificationRead`를 유지합니다. 이 내부 이름으로 푸시 기능을 추가하지 마세요. 관리자 등록은 `title`, `message`로 공통 글 한 건을 만들고 `id`, `count: 1`, `ids`를 반환합니다. 이전 클라이언트의 userId는 신규 대상 선택에 사용하지 않습니다. 수정·삭제는 게시글 ID에 적용합니다. API와 실제 브라우저 하네스에서 대상·소유권·입력 검증·필터를 확인합니다.

## 메모 계약

메모 목록은 기존 중앙 제목·숨김 메뉴·＋를 재사용합니다. ＋와 카드 선택은 PC·모바일 모두 전체 화면 편집 페이지입니다. 제목·본문·첨부는 내부 스크롤, 하단 도구는 팝업 내부에 고정합니다. … 메뉴는 색상·고정·검색·폴더·공유·복제·정보·삭제입니다. 저장 실패는 입력을 유지하고 에디터에 오류를 표시합니다. 변경 후 닫기·Escape는 저장하지 않고 닫기 확인을 표시합니다. 공통 하네스 메뉴에 메모가 자동 포함되며 실제 편집 검증은 메모 브라우저 하네스로 수행합니다.


## TODO 직접 수정과 전체 내용 검색

TODO 직접 수정의 입력칸 오른쪽 ＋ 팝업에서 같은 단계·하위 항목을 추가하고 상위로·하위로 이동을 예약한 뒤 저장합니다. 취소는 모든 변경을 버리며 실패하면 입력을 유지합니다. 완료 상태와 기존 자식 항목은 보존하고 새 항목은 미완료입니다. Enter는 현재 항목 안 줄바꿈, Ctrl/⌘+Enter는 저장입니다. 전체 수정창은 한 줄마다 새 항목이며 기존 항목 안 줄바꿈은 `\ ` 접두사로 유지합니다.

일일리스트 돋보기 팝업의 전체 내용 검색은 날짜 조건을 해제하고 본인 일지 전체의 TODO·익일 계획·비고·메모·업무일자를 검색합니다. 결과를 노란색으로 강조하고 ↑ 이전 / ↓ 다음으로 이동합니다. 현재 결과는 진한 색으로 표시하며 접힌 카드도 펼쳐 주변 내용을 확인합니다. 검색 해제는 원문을 복구합니다. HTML을 해석하지 않고 텍스트 노드와 mark만 생성하며 저장 내용은 바꾸지 않습니다. 검색 중 TODO 직접 수정은 마친 후 사용합니다.

## 메모 편집·자동 저장 (2026-10-01)

저장 버튼 없이 입력을 650ms 멈추면 자동 저장합니다. 닫기는 남은 변경 저장 후 목록으로 돌아가고, 실패 시 내용을 유지하며 다시 저장 버튼을 제공합니다. 한글 조합 중에는 저장을 미루고 완료 뒤 저장합니다. 요청은 직렬화하며 저장 응답은 현재 입력을 덮어쓰지 않습니다. 실행 취소·다시 실행은 상단에, 편집 도구는 키보드 위에 표시합니다. 모바일 편집기는 VisualViewport 높이와 offsetTop을 반영하며 더보기 메뉴는 화면 안에서 스크롤합니다. 외부 에디터·아이콘 플러그인 없이 로컬 SVG를 사용합니다.

검증: scripts/verify-memos.cjs에서 자동 저장·재열기·저장 중 입력·실패/재시도·서식/그리기/녹음·PC/모바일을 확인합니다. 키보드 화면 크기는 VisualViewport 축소 시뮬레이션으로 확인했으며 실제 iPhone 키보드의 최종 호환성은 기기 확인이 필요합니다.
공지 관리 검색은 우측 상단 돋보기 → 검색 팝업(검색어·열람 상태) → 조회로 적용합니다. 전체는 조건을 초기화하며, 취소·닫기·Escape는 기존 조건을 유지합니다. 본문에 상시 검색 폼을 두지 않습니다. ＋ 등록은 돋보기 옆에 유지합니다.

## 공통 검색 레이아웃

메모 검색은 본문 입력창이 아니라 헤더 우측 돋보기(＋ 왼쪽) → 검색 팝업입니다. 팝업에서 제목·내용 검색어, 전체·중요·폴더 분류, 정렬을 지정하고 검색으로 적용합니다. 닫기·Escape는 적용하지 않은 입력을 버리며 다시 열면 마지막 적용 조건을 보여 줍니다. 전체 보기는 조건과 정렬을 초기화합니다. UIConfig는 검색 액션과 권한·팝업 ID를 선언하고 UIShell.searchDialog는 열기·적용·취소·초기화 동작을 공통으로 제공합니다. 새 검색 메뉴는 이 모듈을 재사용하고 본문 상시 검색 폼을 추가하지 않습니다. 디자인 하네스의 메모 메뉴에서도 같은 모듈로 검색·전체 보기·취소와 검색 버튼 우측 배치를 검증합니다.


## 하단 계정 아이콘 표시

## 보고서 참조·링크 및 자식 이동

보고서 등록·수정의 TODO·익일 계획·비고·메모와 TODO 직접 수정에서 @를 입력하면 접근 가능한 파일·메모·일지(일정)를 검색합니다. 종류별 필터와 제목·내용 검색, ↑↓·Enter 선택, Escape 취소를 제공합니다. 이메일 주소 안의 @는 열지 않으며 한글 조합 중 Enter는 선택하지 않습니다. #는 표시 이름과 http:// 또는 https:// 주소를 입력하는 링크 팝업입니다. 취소하면 기존 문자를 유지합니다.

참조는 입력 중 저장 표기로 보이며 조회 목록에서는 대상 이름의 링크로 표시됩니다. 링크를 한 번 클릭하면 내용을 조회합니다. 이미지 파일은 현재 일정 위의 미리보기 팝업으로 열리고, 이미지를 누르면 전체 화면으로 확대됩니다. 전체 화면에서 원본 크기·화면에 맞추기를 전환할 수 있습니다. 닫기·Escape·브라우저 뒤로가기는 확대 → 미리보기 → 원래 일정 순서로 돌아갑니다. 메모·일지·일반 파일 참조 상세의 상단 뒤로가기와 브라우저 뒤로가기도 참조를 연 일정으로 복귀하며 기존 검색·필터와 스크롤 위치를 유지합니다. 상세를 새로고침해도 복귀 경로를 유지합니다. 메모 참조의 첨부 이미지도 클릭하여 크게 봅니다. 내부 참조는 고유 ID로 연결하여 대상 이름이 변경되어도 유지합니다. 표시 이름은 삽입 시 이름을 보존합니다. 삭제·접근 권한 없음은 안내를 표시하며 보고서 원문은 유지합니다. 파일 참조는 정보와 다운로드 버튼, 메모 참조는 본문·첨부, 일지 참조는 전체 내용을 보여 줍니다. 외부 링크는 새 탭으로 연결합니다.

TODO 일반 본문은 더블클릭·두 번 탭·Enter/F2로 편집하며 링크 클릭은 편집을 시작하지 않습니다. 모바일에서는 TODO 일반 문구를 빠르게 두 번 탭하세요. 직접 수정 입력칸 오른쪽 44px ＋ 팝업에서 같은 단계 추가·하위 항목 추가를 선택합니다. 팝업 Escape는 팝업만 닫고 수정 중 내용은 유지합니다. 리스트 직접 수정의 상위로·하위로 버튼은 없으며, 오른쪽 점 손잡이를 드래그해 다른 항목의 위·아래로 옮깁니다. 대상 항목과 같은 단계로 이동하고 자식·손자는 함께 유지됩니다. 자식 안으로 부모를 넣거나 다른 일지로 이동할 수 없습니다. 저장 실패 시 기존 위치를 유지합니다. 손잡이에 포커스 후 Alt+↑/↓로도 같은 단계 순서를 바꿀 수 있습니다. 등록·전체 수정 입력창의 단계 변경과 Tab/Shift+Tab도 자식을 함께 이동합니다. 기존 완료 상태·항목 안 줄바꿈은 유지합니다.

드래그 중에는 부모·자식 미리보기가 포인터를 따라 움직이고 놓을 위치에 빈칸이 표시됩니다. 항목 사이 여백에도 놓을 수 있으며 다른 일지에는 이동하지 않습니다. 손잡이는 28px, 단일 줄 항목은 약 40px 높이로 체크박스·본문을 가운데 정렬합니다. ＋ 선택 팝업의 바깥을 누르면 팝업만 닫고 입력을 유지합니다.

## 당겨서 새로고침 (2026-10-02)

사용자·관리자 메뉴에서 화면 맨 위를 아래로 충분히 당긴 후 손을 놓으면 현재 메뉴의 데이터만 다시 조회합니다. 당기는 동안 아이콘과 안내가 표시되며 검색 조건·캘린더 선택 날짜·현재 상세 URL을 유지합니다. 목록 중간의 스크롤·가로 스와이프·짧은 당기기·여러 손가락·터치 취소는 새로고침하지 않습니다. 작성 화면·검색/확인 창·숨김 메뉴·일지 직접 편집/드래그·기존 요청 처리 중에는 동작을 막습니다. 관리자 설정·파일명 입력을 수정한 상태에서도 입력 유실을 방지하기 위해 막습니다. 로그인·가입·비밀번호 입력 화면과 정적 가이드는 새로고침 대상 데이터가 없으므로 적용하지 않습니다. 실패 안내 후 다시 당겨 재시도할 수 있습니다.

`pull-refresh.js/css`는 터치 방향·임계 거리·실행 중 잠금·표시를 담당하고 `ListScroll.mount()`에서 한 번 연결합니다. 업무 어댑터는 `scroll.setRefresh(action, canRefresh)`로 현재 메뉴의 조회만 연결합니다. 새 데이터 메뉴에도 이 어댑터를 연결하세요. 갱신 GET은 AppLoading의 별도 요청 집계로 추적하며 전체 화면 오버레이 대신 당기기 표시를 사용합니다. 저장·삭제 로딩은 기존 공통 처리를 유지합니다. 목록 페이징 감지는 당기기 갱신 동안 실행하지 않으며 새 조회 후 커서를 초기화합니다. 라우트/세션 변경 후 이전 결과는 요청 순번·화면 세대로 무시합니다. `design-harness.html`의 예시 스크롤 목록에서도 당기기를 확인할 수 있고 `npm run test:pull-refresh`는 PC·모바일 및 실제 CDP 터치 이벤트를 검증합니다. 브라우저 검증에는 개발용 Playwright가 필요하며 제품에 포함하지 않습니다. iOS Safari 실기기 검증은 별도로 필요합니다.
