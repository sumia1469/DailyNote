# 개발자 온보딩

## 첫날 목표

로컬에서 예시 계정으로 로그인하고 사용자 4개·관리자 5개 메뉴를 열어 봅니다. 그다음 `npm test`를 통과시키고 디자인 하네스에서 헤더·메뉴·팝업 규칙을 확인합니다. 운영 데이터 연결은 로컬 이해와 검증 후 별도로 진행합니다.

## 준비 및 실행

Node.js 24, npm, Git, 최신 브라우저가 필요합니다. 프런트엔드 빌드 과정은 없습니다. 저장소를 복제한 디렉터리에서 실행합니다.

```bash
npm ci
ADMIN_USERNAME=admin ADMIN_PASSWORD='직접-지정한-8자-이상-비밀번호' npm run init
npm start
```

PowerShell:

```powershell
npm ci
$env:ADMIN_USERNAME='admin'
$env:ADMIN_PASSWORD='직접-지정한-8자-이상-비밀번호'
npm run init
npm start
```

`http://localhost:3000`에 접속합니다. 환경 변수는 실행 셸에서 설정합니다. `.env.example`을 복사하는 것만으로는 자동 적용되지 않습니다. 초기화는 기존 계정을 덮어쓰지 않습니다. `PORT`, `DATA_DIR`, `UPLOAD_DIR`로 개발 환경을 분리할 수 있습니다.

폐쇄망은 허용된 환경에서 `npm ci`로 Redis 패키지를 준비하고 조직 정책에 따라 Node 런타임·소스·필요 npm 의존성을 반입합니다. 프런트엔드 파일은 `public/`에 모두 있고 UI는 외부 CDN·폰트 요청이 없습니다. 로컬 JSON 모드 자체는 Redis 연결 없이 동작합니다. Vercel 전용 설치물을 폐쇄망 UI에 추가하지 않습니다.

## 로딩 순서와 규칙

CSS는 `style.css` → 화면 설정 → 관리자 CSS(해당 화면) → `app-shell.css` → `ui-shell.css` 순서입니다. 공통 UI 계약은 마지막에 적용됩니다. JS는 아이콘·화면 설정 → `ui-config.js` → `ui-shell.js` → 업무 셸·업무 JS 순서입니다. 관리자의 `admin.js`는 데이터 준비 후 공통 설정으로 패널을 표시합니다. 메뉴 DOM ID와 설정의 `panel`·`actions.id`를 일치시킵니다.

## 등록·수정 연결

UIConfig의 액션은 제목·버튼·권한을 선언합니다. 실제 저장은 업무 어댑터가 담당합니다. 관리자 ＋ 클릭은 활성 패널에 따라 공지·업로드·사용자 팝업을 엽니다. `submitDialog`는 중복 제출 방지, 진행 표시, 오류 표시, 성공 종료를 담당합니다. 오류 시 폼을 먼저 초기화하지 않습니다. 수정은 ID와 기존 값으로 팝업을 채워 PUT을 보냅니다. 권한 설정·화면 설정은 본문 폼을 유지합니다.

## 공지 상세 URL

`/#notifications/ID`는 사용자 셸의 상세 라우트입니다. 해시를 사용하므로 정적 호스팅의 별도 rewrite가 필요 없습니다. 상세 데이터를 `GET /api/notifications/:id`로 받아 본문을 `textContent`로 표시합니다. 서버는 세션의 사용자 ID와 공지 소유자를 비교합니다. 성공하면 PUT으로 읽음 처리합니다. 화면 전환 시 요청 버전을 증가시켜 이전 응답이 현재 화면을 바꾸지 않게 합니다. 새로고침·브라우저 뒤로가기·404·401·권한 거부를 검증합니다.

## 검증

```bash
npm test
npm run test:ui
```

디자인 하네스는 `/design-harness.html`에서 사용자·관리자 메뉴를 선택하고 ＋ 팝업, 빈 입력 오류, 저장 상태, 숨김 메뉴와 키보드를 확인합니다. 체크 실행은 현재 뷰포트에서 제목 중앙·가로 넘침·중복 ID·버튼 배치를 검사합니다. 이 페이지는 예시 전용이며 API를 호출하거나 운영 데이터를 저장하지 않습니다.

실제 브라우저의 PC 1440×1000과 모바일 390×844에서 메뉴 전환·팝업·포커스·헤더·목록을 확인합니다. Node UI 계약 테스트만으로 픽셀·브라우저 호환성을 통과했다고 판단하지 않습니다. 브라우저 설치 실패 시 검증 불가를 명시합니다.

## 배포와 운영 인계

Vercel은 `vercel.json`과 `api/index.js`를 사용합니다. 저장소 연결은 환경 변수로 설정하며 토큰·비밀번호를 커밋하지 않습니다. Redis 연결 모드의 세션·자료 저장과 로컬 JSON 모드는 분리되어 있습니다. 운영 Redis에 테스트를 실행하지 않습니다. 신규 AI·개발자는 README와 AGENTS.md를 먼저 읽고 최신 원격 커밋을 확인합니다. 화면 변경 후 문서·하네스·테스트를 함께 갱신하고 커밋한 소스와 배포 소스를 일치시킵니다.

## 선택 브라우저 자동 하네스

개발 환경에 Playwright가 있을 때 npm run test:browser를 실행합니다. 없다면 외부 반입이 허용된 개발 환경에서만 npm install --no-save --package-lock=false playwright와 npx playwright install chromium으로 준비합니다. 이 도구는 프런트엔드나 운영 런타임의 의존성이 아닙니다. PLAYWRIGHT_MODULE_PATH와 BROWSER_EXECUTABLE_PATH로 이미 설치한 도구를 지정할 수 있습니다. UI_CAPTURE_DIR로 캡처 저장 경로를 지정합니다.

스크립트는 매번 독립 임시 JSON·업로드 경로와 랜덤 비밀번호 예시 계정을 만들고 Redis 환경 변수를 사용하지 않습니다. 1440×1000 PC 및 390×844 모바일, 사용자 3개·관리자 5개 메뉴, 상세 새로고침·복귀, 공지 등록·수정·입력 유지, 파일 업로드와 디자인 하네스를 검증하고 20개 캡처를 저장합니다. 캡처 폰트는 검증 기기에 한국어 글꼴이 있어야 하며 제품에 외부 폰트를 추가할 필요는 없습니다.

## 공지사항 기능 (2026-10-01)

이 메뉴는 사이트 내 공지 게시판입니다. 푸시 알림·브라우저 알림 권한·백그라운드 발송을 사용하지 않습니다. 사용자 메뉴는 **공지사항**, 관리자 메뉴는 **공지 관리**입니다. 숫자 배지는 미열람 공지 수입니다. 사용자 목록에서 제목을 누르면 상세페이지로 이동하고 열람 처리합니다. 기존 제목 없는 공지는 내용을 목록 제목으로 표시합니다.

관리자는 ＋ 팝업에서 제목(선택, 최대 120자), 내용(필수, 최대 2000자), 게시 대상을 지정합니다. 전체 활성 사용자를 선택하면 현재 활성·승인된 사용자에게 사용자별 공지 기록을 생성합니다. 이후 가입자에게는 이 수동 공지를 소급 게시하지 않습니다. 목록의 검색·게시 대상·열람 상태 필터와 건수를 이용해 관리합니다. 수정·삭제는 선택한 사용자별 기록에 적용됩니다. 수정하면 해당 사용자의 공지는 미열람으로 돌아가고 수정일을 기록합니다. 전체 대상 공지의 일괄 수정은 제공하지 않습니다. 기존 업데이트 공지의 자동 생성·중복 방지·삭제 이력은 유지합니다.

호환성을 위해 API `/api/notifications`, `/api/admin/notifications`, 상세 URL `#notifications/ID`, 저장소 `notifications`, 권한 키 `notifications`·`notificationRead`를 유지합니다. 이 내부 이름으로 푸시 기능을 추가하지 마세요. 관리자 등록은 `userId: "all"` 또는 사용자 ID, `title`, `message`를 받으며 전체 대상 응답은 `count`, `ids`입니다. 수정은 사용자 ID만 허용합니다. API와 실제 브라우저 하네스에서 대상·소유권·입력 검증·필터를 확인합니다.

## 메모 모듈

`public/memo.js`, `memo.css`는 공통 UIConfig·AppShell에 연결된 바닐라 JS 업무 어댑터입니다. `src/memo.routes.js`는 GET/POST /api/memos 및 GET/PUT/DELETE /api/memos/:id를 제공하고 세션의 userId로 소유권을 검증합니다. `memoRead/Create/Edit/Delete`는 기본 권한입니다. 메모는 datastore의 memos 컬렉션을 사용하며 기존 JSON·Redis 구현에 동일하게 영구 저장됩니다. 목록 API는 큰 첨부·HTML을 제외하고 미리보기 및 첨부 개수만 반환합니다.

본문 HTML은 클라이언트에서 로컬 허용 태그만 남기고 모든 속성을 제거해 렌더링합니다. 붙여넣기는 일반 텍스트입니다. 첨부는 PNG/JPEG/WebP 및 audio WebM/MP4/OGG/WAV/MPEG의 base64 data URL만 허용하며 SVG·외부 URL은 거부합니다. 서버 본문 3MB 제한, 클라이언트 첨부당 2MB·20개 제한을 적용합니다. 실행 취소 이력은 열린 편집기에서 최대 60개이며 저장된 버전 이력과 다릅니다. 녹음 중·권한 대기·저장 중에는 닫기와 중복 저장을 막고 스트림은 종료 시 해제합니다. 메모 목록 응답은 요청 버전으로 오래된 응답을 무시합니다. 공유는 Web Share API 또는 텍스트 파일 내보내기입니다. 서버 측 알람·음성 인식은 구현하지 않습니다.

메모 API 회귀 검증은 test/memos.test.js, 브라우저 회귀는 scripts/verify-memos.cjs로 실행합니다. 실제 마이크 하드웨어·iOS 브라우저는 별도 환경에서 확인하세요. 브라우저 QA는 가상 오디오 장치로 녹음 저장·재열기를 검증합니다.


## TODO 직접 수정과 전체 내용 검색

TODO 직접 수정의 입력칸 오른쪽 ＋ 팝업에서 같은 단계·하위 항목을 추가하고 상위로·하위로 이동을 예약한 뒤 저장합니다. 취소는 모든 변경을 버리며 실패하면 입력을 유지합니다. 완료 상태와 기존 자식 항목은 보존하고 새 항목은 미완료입니다. Enter는 현재 항목 안 줄바꿈, Ctrl/⌘+Enter는 저장입니다. 전체 수정창은 한 줄마다 새 항목이며 기존 항목 안 줄바꿈은 `\ ` 접두사로 유지합니다.

일일리스트 돋보기 팝업의 전체 내용 검색은 날짜 조건을 해제하고 본인 일지 전체의 TODO·익일 계획·비고·메모·업무일자를 검색합니다. 결과를 노란색으로 강조하고 ↑ 이전 / ↓ 다음으로 이동합니다. 현재 결과는 진한 색으로 표시하며 접힌 카드도 펼쳐 주변 내용을 확인합니다. 검색 해제는 원문을 복구합니다. HTML을 해석하지 않고 텍스트 노드와 mark만 생성하며 저장 내용은 바꾸지 않습니다. 검색 중 TODO 직접 수정은 마친 후 사용합니다.

API와 실제 브라우저 하네스에서 대상·소유권·입력 검증·필터를 확인합니다.


## 메모 편집·자동 저장 (2026-10-01)

저장 버튼 없이 입력을 650ms 멈추면 자동 저장합니다. 닫기는 남은 변경 저장 후 목록으로 돌아가고, 실패 시 내용을 유지하며 다시 저장 버튼을 제공합니다. 한글 조합 중에는 저장을 미루고 완료 뒤 저장합니다. 요청은 직렬화하며 저장 응답은 현재 입력을 덮어쓰지 않습니다. 실행 취소·다시 실행은 상단에, 편집 도구는 키보드 위에 표시합니다. 모바일 편집기는 VisualViewport 높이와 offsetTop을 반영하며 더보기 메뉴는 화면 안에서 스크롤합니다. 외부 에디터·아이콘 플러그인 없이 로컬 SVG를 사용합니다.

검증: scripts/verify-memos.cjs에서 자동 저장·재열기·저장 중 입력·실패/재시도·서식/그리기/녹음·PC/모바일을 확인합니다. 키보드 화면 크기는 VisualViewport 축소 시뮬레이션으로 확인했으며 실제 iPhone 키보드의 최종 호환성은 기기 확인이 필요합니다.
공지 관리 검색은 우측 상단 돋보기 → 검색 팝업(검색어·게시 대상·열람 상태) → 조회로 적용합니다. 전체는 조건을 초기화하며, 취소·닫기·Escape는 기존 조건을 유지합니다. 본문에 상시 검색 폼을 두지 않습니다. ＋ 등록은 돋보기 옆에 유지합니다.

## 공통 검색 레이아웃

메모 검색은 본문 입력창이 아니라 헤더 우측 돋보기(＋ 왼쪽) → 검색 팝업입니다. 팝업에서 제목·내용 검색어, 전체·중요·폴더 분류, 정렬을 지정하고 검색으로 적용합니다. 닫기·Escape는 적용하지 않은 입력을 버리며 다시 열면 마지막 적용 조건을 보여 줍니다. 전체 보기는 조건과 정렬을 초기화합니다. UIConfig는 검색 액션과 권한·팝업 ID를 선언하고 UIShell.searchDialog는 열기·적용·취소·초기화 동작을 공통으로 제공합니다. 새 검색 메뉴는 이 모듈을 재사용하고 본문 상시 검색 폼을 추가하지 않습니다. 디자인 하네스의 메모 메뉴에서도 같은 모듈로 검색·전체 보기·취소와 검색 버튼 우측 배치를 검증합니다.


## 큰 파일 전송

파일 관리 클라이언트는 `POST /api/upload`에 `{phase:"start",filename,mime,size}`로 시작하고 반환된 `id`, `chunkSize`로 파일을 나눕니다. `{phase:"part",id,index,data}`를 순서대로 보내며 마지막 조각이 저장되면 파일이 목록에 표시됩니다. 중간 실패는 `{phase:"cancel",id}`로 정리합니다. 취소도 업로드 권한과 업로드 중인 본인 파일만 허용합니다. 미완료 파일은 24시간 후 해당 사용자 목록 조회/새 업로드 때 정리합니다. 조각 크기는 512KB이며 파일 전체 크기를 제한하지 않습니다.

메타데이터 `chunkCount`가 있는 파일은 `GET /api/upload/ID?part=INDEX`로 조각을 내려받고 클라이언트 Blob으로 조립합니다. 조각 없는 기존 파일은 이전 다운로드 경로를 유지합니다. 모든 조회·업로드·삭제에서 기존 파일 권한과 소유권 검증을 유지합니다. 외부 저장소/CDN은 추가하지 않습니다. 메모 사진은 브라우저 Canvas로 필요한 경우에만 최적화하며 기존 메모 저장 한도 안에서 첨부합니다.


## 브라우저 텍스트 불러오기 모듈

`text-import.js/css`는 일지 입력칸과 하네스에 연결되는 바닐라 JS UI입니다. `text-import-core.js`는 텍스트 정규화·인코딩·추가/교체를 공유하고 `text-import-worker.js`는 엑셀·텍스트·DOCX 해석을 별도 Worker에서 수행합니다. PDF.js와 Tesseract도 로컬 Worker를 사용합니다. 취소 시 작업 번호를 변경해 오래된 응답을 무시하며 활성 Worker와 PDF 작업을 종료합니다. OCR 초기화 중 취소는 초기화 완료 즉시 종료하고 결과를 반영하지 않습니다. 원본은 API로 보내지 않습니다.

사용자 승인에 따라 파일 해석용 로컬 라이브러리만 `public/vendor`에 포함했습니다. 프레임워크·UI 플러그인·CDN은 추가하지 않습니다. 파일 목록·버전·출처·라이선스는 `public/vendor/README.md` 및 `manifest.json`을 확인하세요. 배포·폐쇄망 반입에는 vendor 전체를 포함해야 하며 런타임 npm 설치나 네트워크 다운로드를 요구하지 않습니다. 정적 서버는 `.mjs`를 JavaScript MIME으로 제공해야 합니다. 파일을 `file://`로 직접 여는 방식은 지원하지 않습니다.

`npm run test:imports`는 선택적인 개발용 Playwright·JSZip·pdf-lib를 사용합니다. PLAYWRIGHT_MODULE_PATH, QA_NODE_MODULES, BROWSER_EXECUTABLE_PATH를 필요하면 지정합니다. 예시 계정과 임시 저장소로 PC·모바일, 파일 형식·한글 OCR·시트/열·미리보기 수정·추가/교체·취소·재시도·등록 후 재조회·외부 요청 차단을 확인합니다. 사용자 PC에 검증 도구를 설치할 필요는 없습니다.

## 항목 추가 팝업 및 사진 OCR 보정

editor-add-menu.js는 data-editor 대상과 data-action="add-menu" 버튼을 연결합니다. 직접 추가는 ListEditor.addLine, 파일/사진 선택은 TextImport.open을 호출합니다. 본문 편집창 Escape 처리에서 하위 메뉴·불러오기 dialog를 먼저 닫습니다. ## 보고서 참조·링크 및 자식 이동

보고서 등록·수정의 TODO·익일 계획·비고·메모와 TODO 직접 수정에서 @를 입력하면 접근 가능한 파일·메모·일지(일정)를 검색합니다. 종류별 필터와 제목·내용 검색, ↑↓·Enter 선택, Escape 취소를 제공합니다. 이메일 주소 안의 @는 열지 않으며 한글 조합 중 Enter는 선택하지 않습니다. #는 표시 이름과 http:// 또는 https:// 주소를 입력하는 링크 팝업입니다. 취소하면 기존 문자를 유지합니다.

참조는 입력 중 저장 표기로 보이며 조회 목록에서는 대상 이름의 링크로 표시됩니다. 링크는 한 번 클릭해 조회용 상세페이지로 이동하고 새로고침·브라우저 뒤로가기·상단 뒤로가기를 지원합니다. 내부 참조는 고유 ID로 연결하여 대상 이름이 변경되어도 유지합니다. 표시 이름은 삽입 시 이름을 보존합니다. 삭제·접근 권한 없음은 안내를 표시하며 보고서 원문은 유지합니다. 파일 참조는 정보와 다운로드 버튼, 메모 참조는 본문·첨부, 일지 참조는 전체 내용을 보여 줍니다. 외부 링크는 새 탭으로 연결합니다.

TODO 일반 본문은 더블클릭·두 번 탭·Enter/F2로 편집하며 링크 클릭은 편집을 시작하지 않습니다. 모바일에서는 TODO 일반 문구를 빠르게 두 번 탭하세요. 직접 수정 입력칸 오른쪽 44px ＋ 팝업에서 같은 단계 추가·하위 항목 추가를 선택합니다. 팝업 Escape는 팝업만 닫고 수정 중 내용은 유지합니다. 리스트 직접 수정의 상위로·하위로 버튼은 없으며, 오른쪽 점 손잡이를 드래그해 다른 항목의 위·아래로 옮깁니다. 대상 항목과 같은 단계로 이동하고 자식·손자는 함께 유지됩니다. 자식 안으로 부모를 넣거나 다른 일지로 이동할 수 없습니다. 저장 실패 시 기존 위치를 유지합니다. 손잡이에 포커스 후 Alt+↑/↓로도 같은 단계 순서를 바꿀 수 있습니다. 등록·전체 수정 입력창의 단계 변경과 Tab/Shift+Tab도 자식을 함께 이동합니다. 기존 완료 상태·항목 안 줄바꿈은 유지합니다.

참조 구현은 reference-core.js(검증·문자열 직렬화), references.js/css(검색·표시·읽기 상세), reference-harness.js입니다. 기존 API와 소유권·권한을 재사용하며 별도 DB 필드를 추가하지 않습니다. 내부 참조는 `@[표시 이름](files|memos|worklogs:ID)`, 외부 링크는 `#[표시 이름](http(s) URL)`이고 라벨의 대괄호·역슬래시는 이스케이프합니다.
