# DailyNote · 일일 업무 TODO

폐쇄망에서 사용할 수 있는 **바닐라 JavaScript 업무일지**입니다. 사용자·관리자 화면은 중앙 제목, 왼쪽 숨김 메뉴, 우측 ＋ 등록, 등록·수정 팝업이라는 공통 디자인을 사용합니다. 프런트엔드에는 프레임워크·CDN·외부 UI 플러그인이 없습니다. 서버는 Node.js 기본 HTTP 모듈이며 Redis 연결 시에만 npm `redis` 패키지를 사용합니다.

## 처음 시작하는 분

| 대상 | 먼저 볼 내용 | 다음 단계 |
| --- | --- | --- |

| 운영 관리자 | [사용자 온보딩의 관리자 안내](docs/ONBOARDING-USER.md#관리자-첫-설정) | 가입 승인 → 권한 설정 → 알림 배포 |
| 신규 개발자 | [개발자 온보딩](docs/ONBOARDING-DEVELOPER.md) | 설치·로컬 실행 → 테스트 → 디자인 하네스 |
| 다음 AI | [AGENTS.md](AGENTS.md), [UI 디자인 계약](docs/DESIGN-HARNESS.md) | 현재 코드 확인 → 공통 모듈 수정 → 검증 |

실행 중인 사이트의 왼쪽 메뉴에서 **시작 가이드**를 열 수 있습니다. `/onboarding.html`은 사용자·개발자 안내 화면이고 `/design-harness.html`은 공통 디자인과 팝업 동작을 확인하는 독립 하네스입니다. 하네스의 예시 데이터는 서버에 저장되지 않습니다.

## 사용자 화면

- **일일리스트**: ＋로 등록 팝업, 돋보기로 업무일자 검색. 카드의 …에서 복제·수정·내용 복사·접기·삭제. TODO 문구를 눌러 바로 수정하고 체크박스로 완료 처리합니다.
- **알림**: 본문 상단 제목·설명 없이 목록만 표시. 목록 항목을 누르면 `/#notifications/ID` 상세페이지로 이동합니다. 상세 접근 시 읽음 처리하고, 상단 뒤로가기 또는 브라우저 뒤로가기로 돌아갑니다.
- **파일관리**: 목록·등록일·삭제를 표시하고 파일명으로 다운로드합니다. ＋는 파일 등록 팝업입니다.
- **관리자**: 권한이 있는 경우 숨김 메뉴에 표시됩니다. 화면 전환마다 중앙 제목이 현재 메뉴명으로 바뀝니다.

## 관리자 화면

모든 메뉴는 사용자와 동일한 전체 폭·중앙 제목·숨김 메뉴를 사용합니다. 숨김 메뉴 상단에 **업무일지로 돌아가기**가 있습니다.

| 메뉴 | 등록 | 수정·주요 기능 |
| --- | --- | --- |
| 알림 관리 | 우측 ＋ → 알림 등록 팝업 | 목록 수정 → 같은 팝업, 실패 시 입력 유지·오류 표시 |
| 파일 관리 | 우측 ＋ → 업로드 팝업 | 전체 파일 목록, 이름 변경, 다운로드, 삭제 |
| 사용자 설정 | 우측 ＋ → 사용자 등록 팝업 | 수정·비밀번호 초기화 팝업, 가입 승인·반려 |
| 화면·배경 설정 | 별도 ＋ 없음 | 설정 폼과 미리보기, 저장하여 전체 적용 |
| 권한 설정 | 별도 ＋ 없음 | 기본 사용자 권한·관리 기능 권한을 각각 설정 |

## 로컬 실행

Node.js 24를 권장합니다. 설정은 실행 환경의 환경 변수로 전달합니다. `.env.example`을 자동으로 읽는 로더는 없습니다.

```bash
npm ci
ADMIN_USERNAME=admin ADMIN_PASSWORD='로컬에서-직접-지정한-비밀번호' npm run init
npm start
```

`http://localhost:3000`에서 로그인합니다. 초기화는 기존 사용자가 있는 경우 덮어쓰지 않고 중단합니다. Windows PowerShell 방법과 폐쇄망 반입 절차는 [개발자 온보딩](docs/ONBOARDING-DEVELOPER.md)에 있습니다.

```bash
npm test
npm run test:ui
# 선택: 개발 환경에 Playwright가 설치된 경우
npm run test:browser
```

`npm test`는 API·권한·소유권·UI 계약 테스트를 실행합니다. `test:ui`는 외부 브라우저 패키지 없이 메뉴 설정·공통 셸·HTML 연결을 검증합니다. 실제 렌더링은 브라우저에서 하네스를 열어 별도로 확인해야 합니다.

## 저장소와 운영

로컬은 `data/` JSON과 `uploads/` 파일을 사용합니다. 단일 프로세스 개발용이며 동시 쓰기가 많은 운영 환경에는 적합하지 않습니다. `DATA_DIR`, `UPLOAD_DIR`로 위치를 바꿀 수 있습니다. 데이터·세션·실제 파일·비밀 값은 Git에서 제외합니다.

Vercel은 `vercel.json`의 단일 API 진입점과 정적 `public` 파일을 사용합니다. Production·Preview 환경에 다음 환경 변수를 설정하세요.

- `REDIS_URL`: `redis://` 또는 `rediss://` 연결 문자열.
- 또는 `UPSTASH_REDIS_REST_URL`과 `UPSTASH_REDIS_REST_TOKEN`.
- `ADMIN_USERNAME`, `ADMIN_PASSWORD`: 첫 초기 관리자 생성용. 이미 존재하는 계정은 덮어쓰지 않습니다.
- 선택: `TOKEN_EXPIRES_HOURS` (기본 24).

Vercel에서 저장소 미설정 시 API는 503을 반환합니다. Redis는 사용자·일지·알림·파일 메타데이터·Base64 파일을 저장하고 세션 TTL을 관리합니다. 파일은 최대 3MB, 배경 이미지는 최대 1MB입니다. Redis 테스트는 **비어 있는 전용 인스턴스**에서만 `REDIS_TEST_URL=... npm test`로 실행하세요. 운영 Redis에 테스트를 실행하지 마세요.

## 권한과 검증 범위

기본 권한은 `worklogRead/Create/Edit/Delete`, `fileRead/Upload/Download/Delete`, `notificationRead`입니다. 관리 권한은 `notifications`, `files`, `appearance`, `users`, `permissions`입니다. UI를 숨기는 것과 별도로 서버가 매 요청의 권한·소유권을 검증합니다. 알림 상세는 본인 알림만 조회할 수 있습니다. 관리 파일 ＋는 `files`와 `fileUpload` 권한이 모두 있어야 합니다.

자동 테스트는 로그인·가입 승인·비밀번호·권한·일지 CRUD·복제·파일·알림 상세 소유권과 UI 계약을 검증합니다. 화면 검증은 로컬 예시 데이터로 수행하며 실제 운영 사용자 데이터는 사용하지 않습니다. 배포 성공과 실제 운영 Redis·모바일 전체 브라우저 호환성 확인은 별도의 검증 단계입니다.

## 날짜별 업데이트 알림

완료한 변경은 src/releases.json에 날짜-순번과 sourceCommits로 기록합니다. 사용자 알림 조회 시 해당 사용자에게, 관리자 알림 조회 시 활성·승인 사용자 전체에게 한 번씩 영구 저장합니다. 새 사용자는 첫 조회 때 공개된 공지를 받습니다. 읽음·관리자 수정·삭제 상태를 유지하고 삭제 후 다시 생성하지 않습니다. 이후 변경은 후속 공지로 추가하며 구현 전 요청은 완료로 공지하지 않습니다. 다음 AI는 AGENTS.md의 관리 규칙을 따릅니다.
