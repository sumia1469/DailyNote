## 사용자 화면

- **일일리스트**: ＋로 등록 팝업, 돋보기로 업무일자 검색. 카드의 …에서 복제·수정·내용 복사·접기·삭제. TODO 문구를 눌러 바로 수정하고 체크박스로 완료 처리합니다.
- **공지**: 본문 상단 제목·설명 없이 목록만 표시. 목록 항목을 누르면 `/#notifications/ID` 상세페이지로 이동합니다. 상세 접근 시 읽음 처리하고, 상단 뒤로가기 또는 브라우저 뒤로가기로 돌아갑니다.
- **메모**: ＋ 등록 또는 카드 선택으로 제목·내용 편집 팝업. 사진, 글꼴·굵게·기울임·밑줄·목록, 손그림, 음성 녹음, 실행 취소·다시 실행. …에서 색상·고정·메모 내 검색·폴더 이동·공유·복제·정보·삭제. 저장 전 닫기는 변경사항 확인을 표시합니다. 전체·중요·폴더 필터 및 검색·정렬을 제공합니다.
- **파일관리**: 목록·등록일·삭제를 표시하고 파일명으로 다운로드합니다. ＋는 파일 등록 팝업입니다.
- **관리자**: 권한이 있는 경우 숨김 메뉴에 표시됩니다. 화면 전환마다 중앙 제목이 현재 메뉴명으로 바뀝니다.

메모 편집기의 마이크는 **음성 녹음 첨부**입니다. 자동 음성 인식은 외부 서비스 없이 제공하지 않습니다. 마이크는 HTTPS 또는 localhost와 브라우저 권한이 필요합니다. 사진·음성·손그림은 메모와 함께 서버에 저장되며 한 메모는 총 3MB, 첨부 한 개는 2MB, 최대 20개입니다. 전체 폰트는 운영체제의 고딕·명조·고정폭을 사용합니다.

## 로컬 실행

Node.js 24를 권장합니다. 설정은 실행 환경의 환경 변수로 전달합니다. `.env.example`을 자동으로 읽는 로더는 없습니다.

```bash
npm ci
ADMIN_USERNAME=admin ADMIN_PASSWORD='로컬에서-직접-지정한-비밀번호' npm run init
npm start
```

`http://localhost:3000`에서 로그인합니다. 초기화는 기존 사용자가 있는 경우 덮어쓰지 않고 중단합니다. Windows PowerShell 방법과 폐쇄망 반입 절차는 [개발자 온보딩](docs/ONBOARDING-DEVELOPER.md)에 있습니다.

```bash
npm test
npm run test:ui
# 선택: 개발 환경에 Playwright가 설치된 경우
npm run test:browser
```

`npm test`는 API·권한·소유권·UI 계약 테스트를 실행합니다. `test:ui`는 외부 브라우저 패키지 없이 메뉴 설정·공통 셸·HTML 연결을 검증합니다. 실제 렌더링은 브라우저에서 하네스를 열어 별도로 확인해야 합니다.

## 저장소와 운영

로컬은 `data/` JSON과 `uploads/` 파일을 사용합니다. 단일 프로세스 개발용이며 동시 쓰기가 많은 운영 환경에는 적합하지 않습니다. `DATA_DIR`, `UPLOAD_DIR`로 위치를 바꿀 수 있습니다. 데이터·세션·실제 파일·비밀 값은 Git에서 제외합니다.

Vercel은 `vercel.json`의 단일 API 진입점과 정적 `public` 파일을 사용합니다. Production·Preview 환경에 다음 환경 변수를 설정하세요.

- `REDIS_URL`: `redis://` 또는 `rediss://` 연결 문자열.
- 또는 `UPSTASH_REDIS_REST_URL`과 `UPSTASH_REDIS_REST_TOKEN`.
- `ADMIN_USERNAME`, `ADMIN_PASSWORD`: 첫 초기 관리자 생성용. 이미 존재하는 계정은 덮어쓰지 않습니다.
- 선택: `TOKEN_EXPIRES_HOURS` (기본 24).

Vercel에서 저장소 미설정 시 API는 503을 반환합니다. Redis는 사용자·일지·공지·파일 메타데이터·Base64 파일을 저장하고 세션 TTL을 관리합니다. 파일은 최대 3MB, 배경 이미지는 최대 1MB입니다. Redis 테스트는 **비어 있는 전용 인스턴스**에서만 `REDIS_TEST_URL=... npm test`로 실행하세요. 운영 Redis에 테스트를 실행하지 마세요.

## 권한과 검증 범위

기본 권한은 `worklogRead/Create/Edit/Delete`, `fileRead/Upload/Download/Delete`, `notificationRead`입니다. 관리 권한은 `notifications`, `files`, `appearance`, `users`, `permissions`입니다. UI를 숨기는 것과 별도로 서버가 매 요청의 권한·소유권을 검증합니다. 공지 상세는 본인 공지만 조회할 수 있습니다. 관리 파일 ＋는 `files`와 `fileUpload` 권한이 모두 있어야 합니다.

자동 테스트는 로그인·가입 승인·비밀번호·권한·일지 CRUD·복제·파일·공지 상세 소유권과 UI 계약을 검증합니다. 화면 검증은 로컬 예시 데이터로 수행하며 실제 운영 사용자 데이터는 사용하지 않습니다. 배포 성공과 실제 운영 Redis·모바일 전체 브라우저 호환성 확인은 별도의 검증 단계입니다.

## 공지사항 기능 (2026-10-01)

이 메뉴는 사이트 내 공지 게시판입니다. 푸시 알림·브라우저 알림 권한·백그라운드 발송을 사용하지 않습니다. 사용자 메뉴는 **공지사항**, 관리자 메뉴는 **공지 관리**입니다. 숫자 배지는 미열람 공지 수입니다. 사용자 목록에서 제목을 누르면 상세페이지로 이동하고 열람 처리합니다. 기존 제목 없는 공지는 내용을 목록 제목으로 표시합니다.

관리자는 ＋ 팝업에서 제목(선택, 최대 120자), 내용(필수, 최대 2000자), 게시 대상을 지정합니다. 전체 활성 사용자를 선택하면 현재 활성·승인된 사용자에게 사용자별 공지 기록을 생성합니다. 이후 가입자에게는 이 수동 공지를 소급 게시하지 않습니다. 목록의 검색·게시 대상·열람 상태 필터와 건수를 이용해 관리합니다. 수정·삭제는 선택한 사용자별 기록에 적용됩니다. 수정하면 해당 사용자의 공지는 미열람으로 돌아가고 수정일을 기록합니다. 전체 대상 공지의 일괄 수정은 제공하지 않습니다. 기존 업데이트 공지의 자동 생성·중복 방지·삭제 이력은 유지합니다.

호환성을 위해 API `/api/notifications`, `/api/admin/notifications`, 상세 URL `#notifications/ID`, 저장소 `notifications`, 권한 키 `notifications`·`notificationRead`를 유지합니다. 이 내부 이름으로 푸시 기능을 추가하지 마세요. 관리자 등록은 `userId: "all"` 또는 사용자 ID, `title`, `message`를 받으며 전체 대상 응답은 `count`, `ids`입니다. 수정은 사용자 ID만 허용합니다. API와 실제 브라우저 하네스에서 대상·소유권·입력 검증·필터를 확인합니다.


## TODO 직접 수정과 전체 내용 검색

TODO 직접 수정에서 같은 단계·하위 항목을 추가하고 상위로·하위로 이동을 예약한 뒤 저장합니다. 취소는 모든 변경을 버리며 실패하면 입력을 유지합니다. 완료 상태와 기존 자식 항목은 보존하고 새 항목은 미완료입니다. Enter는 현재 항목 안 줄바꿈, Ctrl/⌘+Enter는 저장입니다. 전체 수정창은 한 줄마다 새 항목이며 기존 항목 안 줄바꿈은 `\ ` 접두사로 유지합니다.

일일리스트 돋보기 팝업의 전체 내용 검색은 날짜 조건을 해제하고 본인 일지 전체의 TODO·익일 계획·비고·메모·업무일자를 검색합니다. 결과를 노란색으로 강조하고 ↑ 이전 / ↓ 다음으로 이동합니다. 현재 결과는 진한 색으로 표시하며 접힌 카드도 펼쳐 주변 내용을 확인합니다. 검색 해제는 원문을 복구합니다. HTML을 해석하지 않고 텍스트 노드와 mark만 생성하며 저장 내용은 바꾸지 않습니다. 검색 중 TODO 직접 수정은 마친 후 사용합니다.

## 공지사항 기능 (2026-10-01)

이 메뉴는 사이트 내 공지 게시판입니다. 푸시 알림·브라우저 알림 권한·백그라운드 발송을 사용하지 않습니다. 사용자 메뉴는 **공지사항**, 관리자 메뉴는 **공지 관리**입니다. 숫자 배지는 미열람 공지 수입니다. 사용자 목록에서 제목을 누르면 상세페이지로 이동하고 열람 처리합니다. 기존 제목 없는 공지는 내용을 목록 제목으로 표시합니다.

관리자는 ＋ 팝업에서 제목(선택, 최대 120자), 내용(필수, 최대 2000자), 게시 대상을 지정합니다. 전체 활성 사용자를 선택하면 현재 활성·승인된 사용자에게 사용자별 공지 기록을 생성합니다. 이후 가입자에게는 이 수동 공지를 소급 게시하지 않습니다. 목록의 검색·게시 대상·열람 상태 필터와 건수를 이용해 관리합니다. 수정·삭제는 선택한 사용자별 기록에 적용됩니다. 수정하면 해당 사용자의 공지는 미열람으로 돌아가고 수정일을 기록합니다. 전체 대상 공지의 일괄 수정은 제공하지 않습니다. 기존 업데이트 공지의 자동 생성·중복 방지·삭제 이력은 유지합니다.

호환성을 위해 API `/api/notifications`, `/api/admin/notifications`, 상세 URL `#notifications/ID`, 저장소 `notifications`, 권한 키 `notifications`·`notificationRead`를 유지합니다. 이 내부 이름으로 푸시 기능을 추가하지 마세요. 관리자 등록은 `userId: "all"` 또는 사용자 ID, `title`, `message`를 받으며 전체 대상 응답은 `count`, `ids`입니다. 수정은 사용자 ID만 허용합니다. API와 실제 브라우저 하네스에서 대상·소유권·입력 검증·필터를 확인합니다.

공지 관리 검색은 우측 상단 돋보기 → 검색 팝업(검색어·게시 대상·열람 상태) → 조회로 적용합니다. 전체는 조건을 초기화하며, 취소·닫기·Escape는 기존 조건을 유지합니다. 본문에 상시 검색 폼을 두지 않습니다. ＋ 등록은 돋보기 옆에 유지합니다.

## 공통 검색 레이아웃

메모 검색은 본문 입력창이 아니라 헤더 우측 돋보기(＋ 왼쪽) → 검색 팝업입니다. 팝업에서 제목·내용 검색어, 전체·중요·폴더 분류, 정렬을 지정하고 검색으로 적용합니다. 닫기·Escape는 적용하지 않은 입력을 버리며 다시 열면 마지막 적용 조건을 보여 줍니다. 전체 보기는 조건과 정렬을 초기화합니다. UIConfig는 검색 액션과 권한·팝업 ID를 선언하고 UIShell.searchDialog는 열기·적용·취소·초기화 동작을 공통으로 제공합니다. 새 검색 메뉴는 이 모듈을 재사용하고 본문 상시 검색 폼을 추가하지 않습니다. 디자인 하네스의 메모 메뉴에서도 같은 모듈로 검색·전체 보기·취소와 검색 버튼 우측 배치를 검증합니다.
