## 로컬 실행

Node.js 24를 권장합니다. 설정은 실행 환경의 환경 변수로 전달합니다. `.env.example`을 자동으로 읽는 로더는 없습니다.

```bash
npm ci
ADMIN_USERNAME=admin ADMIN_PASSWORD='로컬에서-직접-지정한-비밀번호' npm run init
npm start
```

`http://localhost:3000`에서 로그인합니다. 초기화는 기존 사용자가 있는 경우 덮어쓰지 않고 중단합니다. Windows PowerShell 방법과 폐쇄망 반입 절차는 [개발자 온보딩](docs/ONBOARDING-DEVELOPER.md)에 있습니다.

```bash
npm test
npm run test:ui
# 선택: 개발 환경에 Playwright가 설치된 경우
npm run test:browser
```

`npm test`는 API·권한·소유권·UI 계약 테스트를 실행합니다. `test:ui`는 외부 브라우저 패키지 없이 메뉴 설정·공통 셸·HTML 연결을 검증합니다. 실제 렌더링은 브라우저에서 하네스를 열어 별도로 확인해야 합니다.

## 저장소와 운영

로컬은 `data/` JSON과 `uploads/` 파일을 사용합니다. 단일 프로세스 개발용이며 동시 쓰기가 많은 운영 환경에는 적합하지 않습니다. `DATA_DIR`, `UPLOAD_DIR`로 위치를 바꿀 수 있습니다. 데이터·세션·실제 파일·비밀 값은 Git에서 제외합니다.

Vercel은 `vercel.json`의 단일 API 진입점과 정적 `public` 파일을 사용합니다. Production·Preview 환경에 다음 환경 변수를 설정하세요.

- `REDIS_URL`: `redis://` 또는 `rediss://` 연결 문자열.
- 또는 `UPSTASH_REDIS_REST_URL`과 `UPSTASH_REDIS_REST_TOKEN`.
- `ADMIN_USERNAME`, `ADMIN_PASSWORD`: 첫 초기 관리자 생성용. 이미 존재하는 계정은 덮어쓰지 않습니다.
- 선택: `TOKEN_EXPIRES_HOURS` (기본 24).

Vercel에서 저장소 미설정 시 API는 503을 반환합니다. Redis는 사용자·일지·공지·파일 메타데이터·Base64 파일을 저장하고 세션 TTL을 관리합니다. 파일 관리 업로드는 원본을 512KB 조각으로 나눠 저장·다운로드하며 앱의 3MB 파일 제한은 없습니다. 저장소 여유 용량과 브라우저 메모리 범위에서 이용할 수 있습니다. 배경 이미지는 최대 1MB입니다. Redis 테스트는 **비어 있는 전용 인스턴스**에서만 `REDIS_TEST_URL=... npm test`로 실행하세요. 운영 Redis에 테스트를 실행하지 마세요.

## 권한과 검증 범위

기본 권한은 `worklogRead/Create/Edit/Delete`, `fileRead/Upload/Download/Delete`, `notificationRead`입니다. 관리 권한은 `notifications`, `files`, `appearance`, `users`, `permissions`입니다. UI를 숨기는 것과 별도로 서버가 매 요청의 권한·소유권을 검증합니다. 공통 공지는 승인된 사용자에게 공개하며 이전 개별 공지는 원래 수신자만 조회합니다. 관리 파일 ＋는 `files`와 `fileUpload` 권한이 모두 있어야 합니다.

자동 테스트는 로그인·가입 승인·비밀번호·권한·일지 CRUD·복제·파일·공지 상세 소유권과 UI 계약을 검증합니다. 화면 검증은 로컬 예시 데이터로 수행하며 실제 운영 사용자 데이터는 사용하지 않습니다. 배포 성공과 실제 운영 Redis·모바일 전체 브라우저 호환성 확인은 별도의 검증 단계입니다.

## 공지사항 기능 (2026-10-01)

이 메뉴는 사이트 내 공지 게시판입니다. 푸시 알림·브라우저 알림 권한·백그라운드 발송을 사용하지 않습니다. 사용자 메뉴는 **공지사항**, 관리자 메뉴는 **공지 관리**입니다. 숫자 배지는 미열람 공지 수입니다. 사용자 목록에서 제목을 누르면 상세페이지로 이동하고 열람 처리합니다. 기존 제목 없는 공지는 내용을 목록 제목으로 표시합니다.

관리자는 ＋ 팝업에서 제목(선택, 최대 120자)과 내용(필수, 최대 2000자)을 작성합니다. 공지는 모든 승인된 사용자가 함께 보는 게시글 한 건이며 이후 가입자도 조회합니다. 관리자 목록도 게시글당 한 번만 표시하고 열람 인원/전체 인원을 보여 줍니다. 제목·내용 검색과 열람/미열람 사용자 있음 필터를 제공합니다. 공통 글 수정·삭제는 전체에 적용하며 수정하면 사용자별 읽음을 초기화합니다. 기존 업데이트 공지 복사본은 releaseId로 연결하고 이전 읽음·상세 URL을 유지합니다. 이전 개별 공지는 원래 게시 대상만 조회하며 동일 시각·제목·내용의 과거 일괄 게시 기록은 관리자 목록에서 묶어 관리합니다.

호환성을 위해 API `/api/notifications`, `/api/admin/notifications`, 상세 URL `#notifications/ID`, 저장소 `notifications`, 권한 키 `notifications`·`notificationRead`를 유지합니다. 이 내부 이름으로 푸시 기능을 추가하지 마세요. 관리자 등록은 `title`, `message`로 공통 글 한 건을 만들고 `id`, `count: 1`, `ids`를 반환합니다. 이전 클라이언트의 userId는 신규 대상 선택에 사용하지 않습니다. 수정·삭제는 게시글 ID에 적용합니다. API와 실제 브라우저 하네스에서 대상·소유권·입력 검증·필터를 확인합니다.

좌측 숨김 메뉴 하단 사용자 이름 오른쪽의 작은 설정 버튼에서 관리자(권한이 있는 사용자만)·비밀번호 변경·로그아웃을 선택합니다. 비밀번호 변경 화면은 X 또는 Escape로 열기 전 메뉴로 돌아갑니다. 임시 비밀번호 변경이 필수인 경우 X는 로그아웃합니다.
완료한 변경은 src/releases.json에 날짜-순번과 sourceCommits로 기록합니다. 사용자·관리자 공지 조회 시 공통 게시글을 한 번만 영구 저장하고 읽음은 사용자별로 기록합니다. 새 사용자는 첫 조회 때 공개된 공지를 받습니다. 읽음·관리자 수정·삭제 상태를 유지하고 삭제 후 다시 생성하지 않습니다. 이후 변경은 후속 공지로 추가하며 구현 전 요청은 완료로 공지하지 않습니다. 다음 AI는 AGENTS.md의 관리 규칙을 따릅니다.

## 공지사항 기능 (2026-10-01)

이 메뉴는 사이트 내 공지 게시판입니다. 푸시 알림·브라우저 알림 권한·백그라운드 발송을 사용하지 않습니다. 사용자 메뉴는 **공지사항**, 관리자 메뉴는 **공지 관리**입니다. 숫자 배지는 미열람 공지 수입니다. 사용자 목록에서 제목을 누르면 상세페이지로 이동하고 열람 처리합니다. 기존 제목 없는 공지는 내용을 목록 제목으로 표시합니다.

관리자는 ＋ 팝업에서 제목(선택, 최대 120자)과 내용(필수, 최대 2000자)을 작성합니다. 공지는 모든 승인된 사용자가 함께 보는 게시글 한 건이며 이후 가입자도 조회합니다. 관리자 목록도 게시글당 한 번만 표시하고 열람 인원/전체 인원을 보여 줍니다. 제목·내용 검색과 열람/미열람 사용자 있음 필터를 제공합니다. 공통 글 수정·삭제는 전체에 적용하며 수정하면 사용자별 읽음을 초기화합니다. 기존 업데이트 공지 복사본은 releaseId로 연결하고 이전 읽음·상세 URL을 유지합니다. 이전 개별 공지는 원래 게시 대상만 조회하며 동일 시각·제목·내용의 과거 일괄 게시 기록은 관리자 목록에서 묶어 관리합니다.

호환성을 위해 API `/api/notifications`, `/api/admin/notifications`, 상세 URL `#notifications/ID`, 저장소 `notifications`, 권한 키 `notifications`·`notificationRead`를 유지합니다. 이 내부 이름으로 푸시 기능을 추가하지 마세요. 관리자 등록은 `title`, `message`로 공통 글 한 건을 만들고 `id`, `count: 1`, `ids`를 반환합니다. 이전 클라이언트의 userId는 신규 대상 선택에 사용하지 않습니다. 수정·삭제는 게시글 ID에 적용합니다. API와 실제 브라우저 하네스에서 대상·소유권·입력 검증·필터를 확인합니다.

공지 관리 검색은 우측 상단 돋보기 → 검색 팝업(검색어·열람 상태) → 조회로 적용합니다. 전체는 조건을 초기화하며, 취소·닫기·Escape는 기존 조건을 유지합니다. 본문에 상시 검색 폼을 두지 않습니다. ＋ 등록은 돋보기 옆에 유지합니다.

## 공통 검색 레이아웃

메모 검색은 본문 입력창이 아니라 헤더 우측 돋보기(＋ 왼쪽) → 검색 팝업입니다. 팝업에서 제목·내용 검색어, 전체·중요·폴더 분류, 정렬을 지정하고 검색으로 적용합니다. 닫기·Escape는 적용하지 않은 입력을 버리며 다시 열면 마지막 적용 조건을 보여 줍니다. 전체 보기는 조건과 정렬을 초기화합니다. UIConfig는 검색 액션과 권한·팝업 ID를 선언하고 UIShell.searchDialog는 열기·적용·취소·초기화 동작을 공통으로 제공합니다. 새 검색 메뉴는 이 모듈을 재사용하고 본문 상시 검색 폼을 추가하지 않습니다. 디자인 하네스의 메모 메뉴에서도 같은 모듈로 검색·전체 보기·취소와 검색 버튼 우측 배치를 검증합니다.



## 사진·파일에서 텍스트 불러오기

일지 등록·수정 팝업의 TODO·익일 계획·메모 입력칸 아래의 한 줄 도구에서 **항목 추가**를 누르면 **직접 항목 추가 / 사진에서 불러오기 / 파일에서 불러오기** 선택 팝업이 열립니다. 파일 선택 → 텍스트 읽기 → 미리보기 수정 → 기존 내용 뒤에 추가 또는 전체 교체 → 에디터에 넣기 순서입니다. 넣기 전에는 기존 내용을 바꾸지 않으며, 취소·Escape는 가져오기만 닫습니다. 일지는 기존 등록·수정 버튼으로 저장합니다.

지원: PNG/JPEG/WebP/BMP 사진, XLSX/XLS/ODS/CSV/TSV, TXT/MD/LOG/JSON/XML/HTML, DOCX, 텍스트 PDF. 엑셀은 시트와 모든 열/특정 열을 선택하며 셀의 표시 문자열을 읽습니다. 매크로·수식을 실행하지 않습니다. 텍스트는 UTF-8/UTF-16/CP949 자동 인식 또는 직접 선택합니다. 줄바꿈을 유지하고 엑셀 열 사이는 공백으로 구분합니다. TODO·익일 계획에서는 한 줄마다 새 항목입니다. 문서 서식·표 구조를 그대로 재현하는 기능은 아니며 사진·PDF의 읽기 순서는 원본과 다를 수 있습니다.

사진 OCR은 인쇄 글자·스크린샷에 적합하며 손글씨·흐릿한 사진은 오인식될 수 있습니다. 한국어+영어 또는 언어 하나를 선택할 수 있습니다. 작은 사진은 크기를 보정하고 낮은 품질이면 대비·배치를 바꿔 한 번 더 읽습니다. 사진 글자 배치(자동/한 열/흩어진 글자)와 방향을 선택할 수 있으며 품질이 낮으면 경고를 표시합니다. 경고가 없어도 원본과 비교해 확인하세요. 스캔 PDF는 텍스트 추출 대상이 아니며 페이지를 사진으로 저장해 사진 불러오기를 사용합니다. 암호화 문서는 해제한 파일을 사용하세요. HWP/DOC/HEIC는 지원하지 않습니다.

추출은 브라우저 안에서 수행하며 원본 파일을 서버나 외부 서비스에 업로드하지 않습니다. 모든 처리 파일을 사이트의 `public/vendor/`에 포함하므로 인터넷·별도 프로그램 설치가 필요 없습니다. 기존 로컬 웹서버는 실행해야 합니다. 처음 사진 불러오기에는 엔진 로딩 시간이 필요하며 큰 파일은 기기 메모리와 처리 시간을 사용합니다.

사진 불러오기의 기본 가져올 내용은 **본문 글자만**입니다. 알아볼 수 있는 표 선·체크박스 기호를 정리하며 영문·숫자·문장부호는 유지합니다. **인식 원문 그대로**로 전환해 원래 결과를 확인할 수 있으며 방식별 수정 내용을 보존합니다. 선을 J·I처럼 실제 문자로 잘못 읽은 경우에는 본문과 구분할 수 없어 자동 삭제하지 않으므로 직접 수정해 주세요. 이 정리는 사진 OCR 결과에만 적용하며 엑셀·텍스트 파일의 내용은 유지합니다.

## 보고서 참조·링크 및 자식 이동

보고서 등록·수정의 TODO·익일 계획·비고·메모와 TODO 직접 수정에서 @를 입력하면 접근 가능한 파일·메모·일지(일정)를 검색합니다. 종류별 필터와 제목·내용 검색, ↑↓·Enter 선택, Escape 취소를 제공합니다. 이메일 주소 안의 @는 열지 않으며 한글 조합 중 Enter는 선택하지 않습니다. #는 표시 이름과 http:// 또는 https:// 주소를 입력하는 링크 팝업입니다. 취소하면 기존 문자를 유지합니다.

참조는 입력 중 저장 표기로 보이며 조회 목록에서는 대상 이름의 링크로 표시됩니다. 링크를 한 번 클릭하면 내용을 조회합니다. 이미지 파일은 현재 일정 위의 미리보기 팝업으로 열리고, 이미지를 누르면 전체 화면으로 확대됩니다. 전체 화면에서 원본 크기·화면에 맞추기를 전환할 수 있습니다. 닫기·Escape·브라우저 뒤로가기는 확대 → 미리보기 → 원래 일정 순서로 돌아갑니다. 메모·일지·일반 파일 참조 상세의 상단 뒤로가기와 브라우저 뒤로가기도 참조를 연 일정으로 복귀하며 기존 검색·필터와 스크롤 위치를 유지합니다. 상세를 새로고침해도 복귀 경로를 유지합니다. 메모 참조의 첨부 이미지도 클릭하여 크게 봅니다. 내부 참조는 고유 ID로 연결하여 대상 이름이 변경되어도 유지합니다. 표시 이름은 삽입 시 이름을 보존합니다. 삭제·접근 권한 없음은 안내를 표시하며 보고서 원문은 유지합니다. 파일 참조는 정보와 다운로드 버튼, 메모 참조는 본문·첨부, 일지 참조는 전체 내용을 보여 줍니다. 외부 링크는 새 탭으로 연결합니다.

## 공통 메뉴 로딩

`loading.js`와 `loading.css`를 업무 어댑터보다 먼저 로드합니다. 같은 출처의 `/api/` fetch 요청을 공통 추적하며 응답 본문(JSON·파일)을 읽는 동안에도 표시합니다. `AppLoading.begin(message)`는 중복 호출에 안전한 종료 함수를 반환하고 `AppLoading.run(message, action)`은 finally에서 종료합니다. 동시 요청은 마지막 요청까지 유지하고 최소 360ms 표시합니다. 화면 전환·로그아웃은 `AppLoading.clear()`로 이전 화면 작업을 분리합니다. 네트워크 요청이 없는 메뉴 진입도 렌더링 동안 표시합니다. 폴링(`reminders=1`)과 메모 자동 저장은 인라인 상태를 유지합니다. 외부 요청·OCR 로컬 파일은 추적하지 않습니다. 포커스를 이동하지 않으며 메뉴 이동·취소를 막지 않습니다. 지원 브라우저에서는 manual popover로 모달 위에도 표시하며 미지원 환경은 fixed 레이어입니다. 디자인 스킨은 기존 spinner DOM을 유지하므로 별도로 변경할 수 있습니다. `npm run test:common-loading`으로 지연·동시 요청·실패·취소·화면 전환·PC/모바일을 확인합니다.

## 사용자 메뉴 순서

일일리스트 → 캘린더 → 메모 → 공지사항 → 파일관리 → 공유게시판 순서입니다. 업무 공간 구분은 파일관리 아래에 표시합니다. 공유게시판은 여섯 번째 기본 메뉴이며 개별 게시판은 저장한 메뉴 순서(작은 숫자 먼저, 같은 숫자는 ID 순서)에 따라 이어집니다. 게시판 그룹이 달라도 순서를 바꾸지 않습니다. 숨김·비활성 게시판은 개별 메뉴에서 제외합니다.
